# Deploying QuantFolio Agents

The cloud layout:

```text
Browser ──► Vercel (Next.js UI, web/)
               │  HTTPS (REST + live progress over SSE)
               ▼
            Render (Docker: FastAPI API + the risk and compliance A2A agents)
               │  TLS
               ▼
            Neon (Postgres)
```

The database holds everything that must survive a restart:
* runs and their events;
* memory: reviews, preferences and notes;
* the research cache;
* the hash-chained audit log;
* the LangGraph checkpoints, so a plan waiting for approval survives a redeploy;
* the paper-broker ledger;
* the clients you add.

The search models and the RAG index are baked into the Docker image, so the container needs no
disk of its own.

Do the steps in this order: Neon, then Render, then Vercel, then back to Render once for the
Vercel address. It takes about 30 minutes, most of it waiting for the first build.

## 1. Neon (database)

1. Sign in at [neon.tech](https://neon.tech) and create a project:
   * **Region:** AWS Asia Pacific (Singapore), or the region closest to your users. Render
     should use the matching region (step 2).
   * **Database name:** `quantfolio`.
2. On the project dashboard, press **Connect** and copy the connection string. It looks like:
   `postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/quantfolio?sslmode=require&channel_binding=require`.
   Use it exactly as shown; the app converts it for each driver. Pooled or direct both work
   (prepared statements are switched off), but direct is simpler for a single server.
3. Nothing else is needed. The app creates its tables on first start.

Neon's free plan is enough for a demo. It suspends the database when idle; the app checks and
replaces closed connections, so the first request after a pause just takes a moment longer.

## 2. Render (backend)

1. Sign in at [render.com](https://render.com) with GitHub and allow access to the repository.
2. Choose **New > Blueprint**, pick the repository and press **Connect**. Render reads
   `render.yaml` and proposes one web service, `quantfolio-api`.
3. Fill in the secret values it asks for:

   | Variable | Value |
   |---|---|
   | `DATABASE_URL` | the Neon connection string from step 1 |
   | `GROQ_API_KEY` | your Groq key |
   | `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY` | your Langfuse keys (optional) |
   | `CORS_ORIGINS` | leave `[]` for now and fill it in step 4 |
   | `CORS_ORIGIN_REGEX` | leave empty for now |

   `APPROVAL_SECRET` is generated by Render. Keep it: it signs the approval tokens.
4. Press **Apply**. The first build takes about 10 minutes, because it downloads the search
   models into the image. When it is live, open `https://quantfolio-api.onrender.com/health`
   (your service address). It should show `"status":"ok"` and, after a few seconds,
   `"rag_index_ready":true`.

**Plan.** `render.yaml` asks for **Standard** (2 GB of memory, paid). The embedding and reranker
models need about 1 GB once loaded, and the 512 MB plans (Free, Starter) run out of memory. The CI
workflow prints the container's memory use after start (job `docker`), so you can check it. The
Free plan also sleeps after 15 idle minutes, and its first request then takes up to a minute.

## 3. Vercel (frontend)

1. Sign in at [vercel.com](https://vercel.com) with GitHub and choose **Add New > Project**.
   Import the repository.
2. Set **Root Directory** to `web`. Vercel detects Next.js by itself.
3. Under **Environment Variables**, add `NEXT_PUBLIC_API_URL` with your Render address, for
   example `https://quantfolio-api.onrender.com` (no trailing slash).
4. Press **Deploy**. Note the address, for example `https://quantfolio-agents.vercel.app`.

## 4. Connect them (CORS)

Back in Render, open the service, then **Environment**:

* `CORS_ORIGINS` = `["https://quantfolio-agents.vercel.app"]` (your Vercel address, with the
  quotes and brackets);
* optionally `CORS_ORIGIN_REGEX` = `https://quantfolio-agents-.*\.vercel\.app`, so Vercel's
  preview deployments work too.

Save. Render redeploys in about a minute. Open the Vercel address: the header should say
**Ready · groq**.

## Checking it works

* `GET /health` on Render: `status ok`, the LLM, Langfuse on, index ready.
* In the UI, run the example request for GreenLeaf. The decision box appears in about 20 seconds.
* Approve it, then redeploy on Render. The run, its audit trail and the new account value are
  still there, because they live in Neon.
* Add a client, restart the Render service: the client is still on the home page.

## Security notes

* No secret is in the repository. Everything secret lives in Render and Vercel settings.
* The browser talks to the API directly, so no API key is sent from the browser (it would be
  visible to anyone). The API is protected by CORS, a per-address rate limit on new runs
  (Render's proxy address is replaced by the real client address via `--proxy-headers`), a
  request size limit, the guardrails, and approvals bound to the exact orders. To lock the API
  down further, set `API_KEY` on Render and put a server-side proxy in front.
* Trades are paper trades: the broker never touches real money.

## Running the same thing locally

* **With Docker:** `docker compose up --build`. It starts Postgres in place of Neon, the API, the
  two A2A agents as separate services, and the UI on http://localhost:3000. On Windows, Docker
  Desktop needs WSL 2 (`wsl --install` in an admin PowerShell, then restart).
* **Without Docker:** leave `DATABASE_URL` unset and everything uses SQLite files in `data/`.
* **The tests against Postgres, without Docker:**
  `uv run --with pgserver python scripts/test_postgres.py`.
